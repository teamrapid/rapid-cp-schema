    rapid_cp_schema

    Schema for RAPID computable phenotype (CP) logic files, named <cp_name>.yaml, e.g. RAPID000123-xlh_L1_v1.0.yaml. Data-model-independent. Says WHAT counts as evidence (features, coded in source vocabularies: ICD10CM, SNOMED, LOINC, RxNorm, ...) and HOW the evidence combines (Level 1 disjuncts, Level 2a rules, Level 2b score). Every disjunct / rule / score item carries a stable id (d1, r2, s3) that is reported back as the flag reason.

    URI: https://mendelian.co/schemas/rapid-cp-logic

    Name: rapid_cp_schema

    Classes

    Class Description
    ClinicalReview Expert sign-off on the disease and its criteria, before the CP is tested at a site.
    ClusterScope Limits the search to patients who have at least one of the umbrella codes. Every criterion is then evaluated only for those patients.
    CodeRef A code written as it appears in its source vocabulary, never as an OMOP concept_id.
    ComputablePhenotype One versioned CP. File name must equal cp_name + .yaml.
    CPProvenance Who wrote this CP version and when.
    DiseaseRef The disease entity a CP is for, identified by a RAPID disease entity id and an anchor Mondo id.
    Disjunct A Level 1 criterion: one S1 feature that is enough on its own to flag a patient. Its id is reported with the counts.
    ExpectedFlagRate Range of patients per 100,000 a correct CP should flag at a site.
    Expr One condition in a Level 2A rule. Each node uses exactly one form: feature, all_of, any_of, none_of (none of the listed conditions holds), at_least with of, or within. A rule must contain at least one feature that isn't under none_of. min_distinct_dates and min_span_days apply only to a feature node.
    Feature One piece of evidence: a set of codes for one module, plus the result or genetic finding that must be found where the module needs one. Logic blocks refer to features by id.
    GeneticCriterion The variant result a genetic_finding feature looks for: a causal gene and the interpretations that count, such as pathogenic or likely pathogenic. A record matches when it carries one of the feature's codes, its interpretation is one of those listed (if any are), and, when require_gene_text_match is true, the gene symbol appears in the record's text.
    ResultCriterion The result a test or measurement record must have to count: a numeric comparison or a set of accepted answers.
    Rule A Level 2A criterion: a Boolean condition over features. A patient is flagged if any rule holds; each rule's id is reported with the counts.
    ScoreItem A Level 2B score item: points added when its feature is present. Its id is reported with the counts.
    ScoreModel The Level 2B logic: a patient is flagged when the points of the items that apply add up to the threshold.
    Within A record of each listed feature, all falling within days of each other. With in_order, the records must also occur in the listed order (the same day counts as in order).

    Enumerations

    Enumeration Description
    CodeSystem CP-side vocabulary names.
    CPLevel How a CP's features combine into a flag. The level decides which logic block the CP carries: disjuncts (L1), rules (L2A) or score (L2B); L3 has none yet.
    FlagRateBasis Where the numbers in an expected flag rate come from.
    Module The evidence domain a feature belongs to. Drives which OMOP tables are searched and which vocabularies are allowed.
    ResultKind Whether a result is compared with a threshold or matched against a set of accepted answers.
    ResultOperator How a numeric result is compared: with a fixed threshold, a fixed range, or the normal range recorded with the result.
    ReviewDecision The outcome of a clinical review of a CP.
    SearchMode Which patients a CP searches: the whole dataset, or only those with an umbrella code.
    SpecificityGrade How specific a feature is to the target disease. The grade decides what counts as safe alone in L1.
